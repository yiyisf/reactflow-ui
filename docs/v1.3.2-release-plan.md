## 1.4.0 启动前要定的事与已知限制

1.3.2 合并后、1.4.0 开工前，需要先定下面 3 件事。

- **实例隔离**：`workflowStore` 与 `ruleEngine` 仍是全局单例（`ideStoresContext.tsx` 里记为后续工作），同页挂业务 IDE 和 AI IDE 会共用画布状态和校验规则。1.4.0 的审核流与影子运行要不要先拆，决定 E27 怎么做。
- **默认主题色**：`themeColor` 默认仍是已弃用的 `blue`，与「全站 CMASTER 橙色」不一致；改默认值会影响没传这个 prop 的宿主，需要定是 1.4.0 改并写进升级说明，还是留到 2.0。
- **执行验证的语义**：R19 修复二选一，执行前提示「运行已保存版本」，或随请求带上画布定义（Conductor 支持在启动请求里内联定义，但治理服务是否放行要确认）。

沿用 1.3.1 的已知限制：依赖外部系统的任务在沙箱里仍用模拟数据；jq 只支持常用子集；脚本按 ECMAScript 语义执行，不模拟 GraalJS 的 Java 互操作。
