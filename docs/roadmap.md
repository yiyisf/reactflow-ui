# 演进路线图

> 更新：2026-10-22 · 适用版本：v1.1.0 之后

## 定位

`@yiyi_zhang/reactflow-ui` 有两重身份：

1. **工作流 IDE 的 SDK**：在这里验证能力，再由内部项目引入。演示站（Demo）没有接后端，用的是演示数据；内部项目引入时，由宿主通过扩展点（Provider / 回调）接入治理服务、Conductor 与内部模型 API。
2. **前沿探索的实验场**：探索"人与 AI 共同设计、验证、运营流程"的工作台形态，对齐业界方向。

两重身份用**稳定线**与**实验线**区分：

| | 稳定线 | 实验线（Labs） |
|---|---|---|
| 入口 | `@yiyi_zhang/reactflow-ui`、`/ai` | 新增 `@yiyi_zhang/reactflow-ui/labs` |
| 兼容承诺 | 遵循语义化版本，破坏性变更只在大版本 | 不承诺兼容，可随时调整或移除 |
| 默认状态 | 开启 | 宿主显式引入或打开开关才生效 |
| 毕业条件 | — | 至少一个内部项目试用、接口稳定两个小版本后并入稳定线 |

## 原则

- **SDK 不直连后端**：所有数据与能力经扩展点接入；每个新扩展点同时提供契约文档与 Demo 用的模拟实现，内部项目只按契约对接后端，不改 SDK 代码。
- **不接扩展点时行为不变**：新能力默认关闭或降级，已接入的项目升级无感。
- **小步发版**：每个小版本一个主题，2–4 周一版，服务推广节奏（年底接入 10 个系统）。

## 版本计划

| 版本 | 主题 | 目标时间 | 主要内容 |
|---|---|---|---|
| **v1.2.0** | 流程库就绪 | 2026-10-30 | 流程库数据源（已完成）、业务域与命名规范（已完成）、Demo 演示后端、宿主接入指南、质量收尾 |
| **v1.3.0** | 自助接入 | 2026-11-13 | 扩展点注册机制、自助接入向导（`OnboardingProvider`，含命名生成器）、接口导入（OpenAPI / curl → HTTP 任务）、接入漏斗埋点（`TelemetrySink`） |
| **v1.4.0** | 放心上线 | 2026-12-11 | 发布审核流（`ReviewProvider`）、影子运行与一键回滚、AI 产出体检报告、默认可靠性模板、系统价值报告 |
| **v1.5.0** | 持续好用 | 2027 Q1 | Schema 助手（`ExecutionSampleProvider`）、模板中心接入组织模板源（`TemplateProvider`）、新手引导与"解释这个流程" |
| **Labs** | 前沿探索 | 与稳定线并行 | 先做：可验证的意图到流程、历史回放回归；之后：能力即工具（MCP）、智能体编排、执行自愈、流程挖掘、类型化数据流、流程即代码 |

v1.3.0 卡在灯塔团队陪跑期（11 月）中段：陪跑先用 v1.2.0 + HTTP 任务起步，自助向导与接口导入在陪跑中途上线，并按灯塔反馈修正。

## 扩展点总表

| 扩展点 | 用途 | 引入版本 | 内部引入时的后端 |
|---|---|---|---|
| `onSave` / `onWorkflowChange` | 保存定义 | 已有 | 治理服务（含命名与归属校验） |
| `onTriggerExecution` / `onPollExecution` / `executionActions` | 执行与操作 | 已有 | 治理服务转发 Conductor |
| `aiConfig` | 模型调用 | 已有 | 内部模型 API |
| `libraryProvider` | 流程库目录与版本 | v1.2.0 | 治理服务 `/api/library/*` |
| `OnboardingProvider` | 试用、产品、业务域、上线申请 | v1.3.0 | 治理服务自助试用接口 |
| `TelemetrySink` | 接入漏斗与使用事件 | v1.3.0 | 治理服务事件接口 |
| `ReviewProvider` | 发布审核与影响范围 | v1.4.0 | 治理服务审核与引用索引 |
| `ExecutionSampleProvider` | 按权限取执行样本 | v1.5.0 | 治理服务执行查询 |
| `TemplateProvider` | 组织模板存取 | v1.5.0 | 治理服务模板接口 |

服务端对应能力见《流程库服务端配合方案》与《流程库服务端 AI 实施指南》；推广节奏见《编排平台推广计划》。
