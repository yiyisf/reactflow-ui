# AiWorkflowIDE 体验重设计方案

> 状态：待评审
> 前提：主要用户为**业务/运营人员**；布局维持**对话优先**（画布为抽屉）；三大场景（0→1 创建、修改存量、运行态排障）均需覆盖。

---

## 一、问题诊断

测试反馈为"整体不满意但说不清具体点"。经代码走查 + 用户确认，根因可归纳为一句话：

> **决策时刻信息不足，等待时刻反馈缺失，对话时刻被打断，全程观感偏 demo。**

| # | 痛点 | 现状根因 |
|---|------|----------|
| 1 | 审查时看不清改了什么 | 提案卡只有 `+5 新增 ~2 修改` 数字 chip 和 ref 名；画布默认关闭；Mermaid 图在**接受之后**才出现——预览与决策时序颠倒 |
| 2 | 生成过程反馈弱 | 流式期间只有一行 `正在生成新工作流…`，没有流程逐步成形的感觉；自愈重试完全静默 |
| 3 | 对话流被打断 | pending proposal 时发消息弹出 guard 对话框强制"放弃/审核"二选一；提案不可通过继续对话来迭代 |
| 4 | 观感不精致 | 全 emoji 图标（🚀🗺️⚙️✨）；5 套建议 chips 并存；5 种卡片各有各的样式；审查 UI 双轨（聊天卡 + ReviewBar） |

**对业务用户的含义**：他们不看 JSON、不认识 taskReferenceName，唯一能建立信任的方式是"**看到流程本身**"。当前所有关键信息都以技术形态（ref 名、diff 统计）呈现，业务用户全程处于半盲状态——这就是那种说不出的"不踏实"。

---

## 二、设计原则

1. **生成即所见**：AI 产出的任何方案，在用户做决定**之前**就以业务语言可视化。
2. **对话永不阻断**：提案是对话的一部分，可以用继续说话来修改它，而不是模态的"接受/拒绝关卡"。
3. **过程即叙事**：AI 工作的每一步（搜库、编排、校验、自愈）都讲给用户听，把黑盒变成信任建设时刻。
4. **一个决策点**：同一时刻只有一处审查入口、一组建议按钮。
5. **产品级质感**：统一图标语言、卡片体系、间距 token。

---

## 三、核心改造

### P0-1 提案预览卡（最高优先级）

**用"流程步骤预览"替换"数字统计"，把 Mermaid 从接受后提前到提案时。**

新的聊天内提案卡（唯一审查入口）：

```
┌──────────────────────────────────────────┐
│ ✦ 变更方案 · 订单处理流程                  │
│ ┌──────────────────────────────────────┐ │
│ │ 1 ⚙️ 下单确认                          │ │   ← 未变更：常规展示
│ │ 2 🌐 支付验证                          │ │
│ │ 3 🛡️ 风控检查                  ＋新增  │ │   ← 绿色左边条 + 底色
│ │ 4 ⚙️ 库存扣减     ～修改·新增失败重试   │ │   ← 黄色 + 一句话说明改动
│ │ 5 ̶📧̶ ̶旧̶通̶知̶步̶骤̶                －删除  │ │   ← 红色 + 删除线
│ │ 6 👤 人工审批                          │ │
│ └──────────────────────────────────────┘ │
│ 共 6 步 · 1 新增 · 1 修改 · 1 删除        │
│                                          │
│ [✓ 应用变更]   [✕ 不用了]   [在画布中查看] │
│ ─────────────────────────────────────── │
│ 💬 也可以直接告诉我还要怎么调整             │
└──────────────────────────────────────────┘
```

要点：
- **步骤预览列表**：用 `proposedDef` + `diff` 渲染，复用 `BusinessCanvas` 的 StepCard 精简版（业务标签 + 图标 + 中文名）。业务用户看到的是"流程变成什么样"，而非 ref 名清单。
- **modified 项附一句话变更摘要**：diff 计算时提取字段级变化（如 `retryCount: 0→3` → "新增失败重试"、`timeoutSeconds: 300→600` → "超时 5 分钟 → 10 分钟"）。做不到语义化时至少列出变更的属性中文名。
- **「在画布中查看」**：打开画布抽屉并进入**幽灵预览模式**——画布渲染 `proposedDef`，新增节点绿色描边、修改黄色、删除的以半透明红色保留原位。关闭预览回到当前版本。
- **接受后**：不再追加整张 Mermaid 大图（当前行为），只追加一行 `📌 已应用「xxx」（6 个步骤）`，同时画布/提案卡定格为"已应用"历史态。Mermaid 业务图只在用户明确要求"解读流程"时生成。

### P0-2 提案可迭代，删除 Guard 对话框

- pending proposal 时**输入框保持可用**，placeholder 改为：`继续描述修改意见，或点击上方"应用变更"`。
- 发送新消息 = **对提案的迭代**：`buildHistory` 注入当前 `proposedDef`（system 注入 `当前有一份未应用的方案 JSON: ...`），AI 基于它产出新提案；新提案卡出现时，旧卡自动折叠为灰色历史态（`已被新方案替代`），不弹任何确认框。
- 彻底删除 `guardBlocked` overlay 及相关状态。
- 接受/拒绝从"模态义务"降级为"随时可做的动作"——用户不点它们也能继续工作。

### P0-3 生成过程叙事化

把单行 `toolStatus` 升级为附着在流式消息上的**工作时间线**：

```
✓ 理解需求
✓ 搜索工作流库 · 找到 2 个可复用子流程
◍ 编排流程 · 已生成 4 个步骤…
○ 校验流程
```

- 每个 agentic step / tool call 映射为一个时间线节点，完成打勾并保留摘要（如搜索命中数、生成步骤数）。
- **自愈可见化**：现在校验失败自动重试是静默的；改为显式节点 `⚠ 发现 2 处校验问题，正在自动修正…` → `✓ 已修正`。这是最强的信任建设时刻，不该藏起来。
- 进阶（可放 P2）：`replace_workflow` 的流式 arguments 做 partial-JSON 解析，实时显示"第 N 步：{步骤名}"，甚至让提案卡骨架逐条长出步骤。

### P1-4 审查界面归一

- **聊天内提案卡是唯一决策点**。画布打开时，`ReviewBar` 退化为只读状态条：`👁 正在预览 AI 方案 — 请在对话中确认`（或直接复用同一组按钮组件，保证行为一致）。
- **砍掉逐项勾选（granular accept）**：对业务用户认知成本过高（勾选 checkbox 决定"应用哪几个节点变更"是工程师心智）。替代方案就是 P0-2：用户直接说"通知步骤别删"，AI 重新出方案——更 AI-native，代码也更简单。`applyPartialProposal` 保留导出供集成方用。

### P1-5 视觉系统整顿

- **图标**：界面级 emoji（🚀🗺️⚙️✨💬📚⏹）全部替换为统一 SVG 图标组件（lucide 风格，16px / stroke 1.5）。业务语义 emoji（步骤类型 ⚙️🌐👤）可保留，它们对业务用户有识别价值。
- **建议 chips 收敛为单一 Suggestion Slot**：任一时刻最多一组、最多 3 个。状态机决定内容：
  - 空画布 + 无库 → 模板画廊（保留，但收敛为两列、去边框噪音）
  - 空画布 + 有库 → 库驱动 chips
  - 有工作流 → 优化建议 chips
  - 刚接受方案 → 继续优化 chips
  - 运行失败/完成 → 失败分析 / 报告 chips（优先级最高）
- **卡片语言统一**：Proposal / Plan / Repair / Clarification / Recommendation 五种卡统一为 `AiCard` 基座（头部：图标+标题；主体；底部动作行，主按钮在右），只有强调色随类型变化。
- **细节**：thinking 三条骨架线 → 打点/呼吸动画；消息气泡、字号、间距走 token；发送按钮用主色实心圆形箭头。

### P2-6 运行态排障闭环

- 执行失败时，banner 下自动附**失败摘要卡**：失败节点业务名 + 错误信息（截断），一键「诊断并给修复方案」（即现有 propose_repair 链路）。
- RepairCard 执行动作后回报结果：触发重跑 → 轮询 → 卡片回填 `✓ 重跑成功` / `✗ 仍然失败，继续分析`，形成闭环而不是"点完就没了"。

## 四、实施拆分

| 阶段 | 内容 | 主要文件 |
|------|------|----------|
| **A（P0）** | ① 提案预览卡 + Mermaid 前置 + 画布幽灵预览入口 ② 删 guard、提案可迭代 ③ 生成时间线（含自愈可见化） | 新 `ProposalPreviewCard.tsx`、新 `AgentTimeline.tsx`；改 `AiCommandCenter.tsx`、`AiWorkflowIDE.tsx`、`toolExecutor.ts`（字段级 diff 摘要）、`systemPrompt.ts`（提案迭代上下文） |
| **B（P1）** | ④ 审查归一（ReviewBar 简化、砍 granular UI） ⑤ 视觉整顿（SVG 图标组件、Suggestion Slot 状态机、AiCard 统一、token） | `ReviewBar.tsx`、新 `icons.tsx`、新 `AiCard.tsx`、`AiNative.css` |
| **C（P2）** | ⑥ 运行态闭环 ⑦ 流式 partial-JSON 步骤实时成形 | `RepairCard.tsx`、`protocolAdapter.ts` |

**验收基准（对应四个痛点）**：
1. 不打开画布也能在 10 秒内看懂 AI 改了什么（每一步是什么、哪里变了）。
2. AI 工作全程有 ≥3 个可见的进度节点，自愈过程可见。
3. 提案悬挂时可直接继续对话修改方案，全程零弹窗。
4. 界面级 emoji 为 0，任一时刻建议按钮 ≤3 个，五种卡片视觉同源。
