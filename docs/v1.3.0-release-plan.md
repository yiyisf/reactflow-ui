# v1.3.0 发布计划：自助接入

> 目标发布：2026-11-13 · 设计见 `docs/design/v1.3.0-自助接入设计.md` · 演进路线见 `docs/roadmap.md`

## 目标

新团队在测试环境里不靠平台方陪跑，也能自己完成"登记产品 → 规范命名建流程 → 接上已有接口 → 试跑 → 申请上线"。正值灯塔团队陪跑期，v1.3.0 在陪跑中途上线并按反馈修正。

## 批次

| 批次 | 内容 | 验收 | 计划 |
|---|---|---|---|
| ✅ B1（本批次） | **扩展点注册**：`IdeProviders`、`WorkflowIdeProvider`、解析顺序与稳定性；**`TelemetrySink`** 核心（批量、flush、事件类型）；Demo `createMockProviders()` | 现有 `libraryProvider` 用法不变；同一 providers 同时服务两个 IDE；单测覆盖解析顺序与批量 | 10-26 – 10-29 |
| B2 | **自助接入向导**：`OnboardingProvider` 契约、`WorkflowNameBuilder`、`OnboardingWizard`、`PromotionPanel`；工具栏入口与空画布引导；Demo 模拟实现 | 新用户在 Demo 中 5 分钟内完成产品登记 → 建流程 → 申请上线（模拟审批）；冲突、失败、生产环境三种降级可演示 | 10-30 – 11-05 |
| ✅ B3（本批次） | **接口导入**：OpenAPI 3 / Swagger 2 / Postman v2.1 / curl 解析，生成 HTTP 业务动作；敏感头占位 | 各格式至少 3 个真实样例的单测；生成的 HTTP 任务可在沙箱试跑 | 11-03 – 11-08 |
| B4 | **埋点铺设与收尾**：首批事件接入、接入指南与 CHANGELOG 更新、走查、宣传页 | 首批事件全部可在 Demo 控制台看到且不含参数值；走查清单通过 | 11-09 – 11-12 |

B2 与 B3 可并行。

## 需服务端配合（并行）

按《AI 实施指南》第九节：`/api/library/domains`、`/api/products/mine`、`/api/onboarding/trial`、`/api/onboarding/promote` 与进度查询；事件接收接口（可与 `wf_onboarding_event` 合用）。服务端未就绪时，内部项目可先用 Demo 的模拟实现联调界面。

## 待确认

见设计文档第 7 节：YAML 依赖、空画布引导、埋点粒度。

## 人工走查清单（B4 前补充完整）

- [ ] 只传 `libraryProvider`（不用 `WorkflowIdeProvider`）时行为与 1.2.0 一致
- [ ] 向导：产品登记、产品冲突、接口失败重试、生产环境下的类型选择
- [ ] 命名生成器：实时预览与校验、层级写入后动作选择器按分层过滤
- [ ] 申请上线：提交、进度刷新、被驳回时的提示
- [ ] 接口导入：四种格式各导入一次、敏感头被替换为占位
- [ ] 埋点：事件可见、不含参数值与对话内容
