LIBRARY

流程库：像积木一样复用标准能力

业务用户在动作选择器里挑选已治理的能力，而不是自己拼装 TaskDef。能力定义直接来自 Conductor 标准的 WorkflowDef / TaskDef，不需要额外的私有格式。

📚 从定义到积木

一份标准定义，自动长成业务动作

入参取自 inputSchema，出参取自 outputSchema / outputParameters；中文字段名与表单由 schema 的标题、描述、枚举、默认值自动生成，业务同学看到的是“配置项类型”而不是 ciType。

① Conductor 标准定义

WorkflowDef {
  name: "std-L1-配置管理-cmdb-query_ci"
  inputSchema:  { ciType, keyword … }
  outputSchema: { ciList, total }
}
→

② 业务动作（表单自动生成）

配置项类型 *下拉 · 服务器…
关键字文本
返回条数数字 · 默认 20
→

③ 编译为 SUB_WORKFLOW

{ "type": "SUB_WORKFLOW",
  "subWorkflowParam": {
    "name": "…query_ci",
    "version": 1 } }
🧩 复用，而不是复制

业务模式里直接挑

  • 动作选择器按业务域分组，搜索跨全部能力
  • 步骤记录 libraryRef，知道引用的是哪个能力的哪个版本
  • 目录加载中 / 失败时显示“加载失败，点击重试”，失败不阻塞编辑
  • 不传 libraryProvider 时，actions / workflowLibrary / taskSchemas 行为不变
VERSION PINNING

版本固定，升级看得见

首次引用时固定版本，库升级后不会自动跟随。有新版本只给出提示，看清差异、你确认之后才升级；固定版本不可用时，流程照常编译。

DOMAIN & LEVEL

业务域与分层

ONE SOURCE · TWO IDEs

一个数据源，两个 IDE

同一份规范化目录（LibraryCatalog）投影成业务动作、AI 任务 Schema 与 AI 流程库目录。宿主只需要接一次。

👔 业务 IDE · WorkflowIDE

目录经 toActions 变成动作选择器里的业务动作，带业务域分组、层级过滤、版本徽标。
libraryProvider

list / get / 可选 search
引用稳定，变化即重新加载

✨ AI IDE · AiWorkflowIDE

目录经 toTaskSchemas / toLibraryItems 并入 AI 的 Schema、目录与检索工具。
🔎 AI 检索

目录与检索

search_workflow_library 支持按业务域过滤。Provider 实现了 search 时检索走服务端，否则在本地目录内匹配（结果最多展示 50 条）。

📌 自动固定

AI 生成的子流程不乱填版本

AI 新建的 SUB_WORKFLOW 引用自动固定为目录当前最新版本；画布上已有的步骤与已有版本号一律不被改动。

📏 大目录

promptCatalogLimit

默认 50。目录注入系统提示词时按层级 L3 → L1 截断，超出部分提示 AI 改用检索工具，治理平台 1000+ 工作流也不会撑爆提示词。

POLISH

        
体验与质量

        
走查中发现的问题和一批性能、工程质量收尾，全部来自 CHANGELOG。

      

      
    
        
  • 🔗下拉字段「插入数据」
    下拉字段可改为引用上游步骤输出或全局入参，也可切回选择；已保存 ${…} 时自动进入动态取值。
    • 
        
  • 🎨弹窗跟随主题
    动作选择、沙箱配置、参数联想弹窗不再在暗色下透明；动作选择弹窗的筛选拆为“分类”“业务域”两行。
    • 
        
  • ⚡卡片视图更跟手
    编辑只更新定义，不再每次按键都做整图布局，切回画布时再补建。
    • 
        
  • 🎯按需订阅
    Store 订阅改为按需（useShallow），逐节点组件不再因无关状态变化而重渲染。
    • 
        
  • ↩️撤销历史上限
    撤销历史上限 100 条，历史比较先做引用相等判断，避免每次都序列化整份定义。
    • 
        
  • 🪆多层嵌套控制流
    分支 / 并行泳道 / 循环体内支持任意层级嵌套控制流。
    • 
        
  • ⌨️输入不再丢焦点
    步骤 ID 不再随时间变化，编辑时不再重建卡片、收起展开项。
    • 
        
  • 🧹展开不再重复信息
    去掉表单顶部与步骤头部重复的名称 / 描述横幅，保留敏感操作提示。
    • 
        
  • 🛡类型检查门禁
    CI 新增阻塞式全量类型检查，并修复了测试与演示代码中原有的类型错误。
    • 
        
  • 🤖AI 版本更稳
    AI 生成子工作流不再随意填版本，新建引用固定为目录当前最新版本。
    • 
        
  • 🔢版本串解析修复
    流程库面板插入子工作流时，不再把 "1.2.0" 这类版本串错误解析成 120。
    • 
        
  • 💬统一对话框
    控制流卡片的原生 alert / confirm 改用项目自带对话框，重复的子步骤列表代码合并为 StepListEditor。
    • 
      

    


    
    

      

        
WHAT'S NEXT

        
接下来

        
小步发版，每个小版本一个主题。每个新扩展点都会同时提供契约文档和 Demo 用的模拟实现，不接扩展点时行为不变。完整计划见 docs/roadmap.md。

      

      
    
        
  • v1.3.0
    自助接入
    目标 2026-11-13
    扩展点注册机制、自助接入向导（OnboardingProvider，含命名生成器）、接口导入（OpenAPI / curl → HTTP 任务）、接入漏斗埋点（TelemetrySink）。
    • 
        
  • v1.4.0
    放心上线
    目标 2026-12-11
    发布审核流（ReviewProvider）、影子运行与一键回滚、AI 产出体检报告、默认可靠性模板、系统价值报告。
    • 
        
  • v1.5.0
    持续好用
    目标 2027 Q1
    Schema 助手（ExecutionSampleProvider）、模板中心接入组织模板源（TemplateProvider）、新手引导与“解释这个流程”。
    • 
        
  • Labs
    前沿探索
    与稳定线并行 · 不承诺兼容
    先做可验证的意图到流程、历史回放回归；之后探索能力即工具（MCP）、智能体编排、执行自愈、流程挖掘、类型化数据流、流程即代码。
    •

TRY IT

        
三分钟，在工作台里走一遍

        
工作台跑在模拟治理服务上，所有流程库能力都是合成的演示数据。

      

      

        

          
    
            
  1. 打开 /app 工作台，使用默认的 👔 业务模式，并保持 💻 经典模式（层级控制只在经典模式下出现）。
    2. 
            
  2. 在“📁 示例工作流...”下拉里选 📚 引用库能力（有新版本 / 版本不可用）。
    3. 
            
  3. 展开步骤，看每个库能力的固定版本徽标；点 ⬆ 有新版本 查看升级差异，确认后才会升级；⚠ 版本不可用 的步骤保持原样编译。
    4. 
            
  4. 试试工具栏 📚 流程库...：“重新加载流程库”，或“模拟加载失败”后点击重试。
    5. 
            
  5. 用 层级：不限 / L1 / L2 / L3 切换当前流程层级，再打开动作选择器添加步骤，观察被隐藏的高层能力。
    6. 
            
  6. 切到 ✨ AI 模式，让 AI 检索并引用库能力（可按业务域），生成的子工作流会带上固定版本。
