沙箱里真的跑一遍

INLINE JQ SWITCH DO_WHILE 等不依赖外部系统的任务，在浏览器里按 Conductor 语义真实执行；依赖外部系统的任务仍用模拟数据，结果里标得清清楚楚。

脚本隔离

脚本碰不到网络

  • v1.3.2 起脚本在 CSP 沙箱 iframe 里运行，每次求值新建 Worker
  • import() FontFace fetch 都发不出请求
  • 一个脚本不能篡改后面脚本的结果，也读不到它们的入参
  • 单个脚本默认 2 秒超时，死循环会被终止
  • 宿主页面不允许沙箱时，如实标为「未执行」并说明原因
入参

模拟入参带对类型

默认模拟入参按 inputSchema 的类型、示例和 inputTemplate 的默认值生成，数字给数字；执行前用 inputTemplate 补齐没给的入参，variables 取定义里的初值。

结果可区分

每个任务都标明来源

任务结果带 sandboxExecution：executed 真实执行、mocked 模拟数据、not_executed 未执行；取不到值的引用记入 sandboxWarnings。

CONDUCTOR SPEC

三种编辑方式，写出同一份规范 JSON

专业编辑器、业务卡片流和 AI 生成的定义都按 Conductor 的字段要求写；在业务模式和画布之间来回切换，定义逐字段不变。

SWITCH 的写法
// 旧写法：DECISION 的字段写在 SWITCH 上，Conductor 保存时会拒绝
{ "type": "SWITCH", "caseValueParam": "level" }

// v1.3.2：校验直接报错并给出改法，AI 规范化自动迁移成
{
  "type": "SWITCH",
  "evaluatorType": "value-param",
  "expression": "level",
  "inputParameters": { "level": "${workflow.input.level}" }
}
往返不变

切来切去，定义不走样

  • 只等部分分支的 FORK，joinOn 原样保留
  • 没有 description / version 的定义不会被补出字段
  • 任务上的 optional retryCount timeoutSeconds 等配置往返不丢
  • 超时与重试策略写进 taskDefinition
校验器

保存前就拦下 Conductor 会拒的写法

新增与补强的检查，每条提示都写明怎么改：

SWITCH 缺 evaluatorType / expression KAFKA_PUBLISH 缺 topic / bootStrapServers EVENT 缺 sink WAIT 同时配了 duration 与 until INLINE 脚本写在 scriptExpression TERMINATE 的 terminationStatus 写错 表达式引用了不存在的任务 FORK 后未紧跟 JOIN joinOn 引用不存在的任务
SAFE BY DEFAULT

修改不丢，权限不越

执行验证、复制粘贴、AI 对话这些日常操作，不再悄悄改掉或带走你的东西。

执行验证

运行完，修改还在

画布有未保存的修改。将运行已保存的版本（order_flow v3），这些修改不会参与本次执行；要验证修改，先保存再执行。

运行视图用实例里的定义渲染，编辑中的定义单独保存；回到编辑态原样换回，不进撤销历史。运行态下保存，存的也是编辑中的定义。

AI 权限

AI 只做你允许的事

  • 只读权限或运行态下，越权的工具调用被拒绝，时间线记一条「已拒绝调用 replace_workflow：当前没有编辑权限」
  • 有可续跑的断点时，新消息先问「继续上次」还是「放弃断点并发送」，不再静默丢弃
  • transport 与请求头不再写进 localStorage
剪贴板

复制的任务只放内存

复制的 HTTP 任务可能带着 Authorization 头，现在不再写进 localStorage；旧版本留下的内容在升级后第一次加载时清除。接口导入时，请求体任意层级的敏感字段都换成 ${workflow.input.…} 占位。

撤销

替换之前先问，替换之后能撤

新建流程、从模板中心选模板会替换画布上的流程时，先确认替换哪个，替换后可以撤销。宿主用受控方式回写定义时，连续编辑也能一步步撤回。

HONEST UI

界面只说真话

状态、数字和提示都来自真实数据；拿不到的就不显示，不再编。

状态

颜色 + 图标 + 中文，处处一致

一套共用的状态映射覆盖 Conductor 的全部任务与工作流状态，节点角标、执行状态栏、任务详情、执行分析、瀑布图与运行故事线显示一致。

运行中 成功 失败 已超时 带错完成 已终止 已跳过 等待中
不再编数字

没有就不写

  • 模板中心去掉编造的使用次数
  • 运行故事线按真实输出生成，缺数据时不写
  • 模板试跑失败时写出失败任务与原因，不再一律「试跑通过」
  • 没接执行回调时不显示「执行验证」

UPGRADE

从 v1.3.0 直接升级

公开接口没有破坏性变更。下面几条行为变化建议升级前看一眼。

WorkflowStudio.tsx · v1.3.2 新增的可选属性
<WorkflowIDE
  workflowDef={def}
  // 传入本地文件、草稿等还没保存的定义时设为 false
  workflowDefSaved={false}
  // 可以返回 Promise：resolve 后才记为已保存，reject 时继续提示未保存
  onSave={async (def) => { await api.saveWorkflow(def); }}
  onTriggerExecution={trigger}
/>

// 用其它方式确认保存了服务端定义后，告诉 IDE 以它为已保存版本
ideRef.current.markSaved(def);
行为变化

升级前看一眼

  1. SWITCH 校验变严：只写了 caseValueParam / caseExpression 的 SWITCH 由警告改为错误；AI 规范化会自动迁移。
  2. 新增必填：EVENT 的 sink，KAFKA_PUBLISH 的 topic 与 bootStrapServers。
  3. 本地缓存清理：升级后第一次加载会删除旧版本存下的剪贴板任务。
  4. 沙箱同步接口：executeLocalSandboxDryRun 不再伪造脚本结果，建议改用 executeLocalSandboxDryRunAsync。
  5. 执行验证入口：没传 onTriggerExecution 时不再显示「执行验证」。
