# v0.4.0 发布计划

> **目标版本**: v0.4.0  
> **核心主题**: AI 参数自动化 × 执行验证闭环 × 智能结果分析  
> **基于**: v0.3.0（已完成库化交付、AI 对话建模、运行态可视化）

---

## 总体目标

v0.4.0 聚焦"从设计到验证"的完整闭环：用户定义工作流 → AI 辅助配置参数 → 一键触发真实执行 → AI 分析执行结果定位问题，形成"设计—验证—修复"的自我闭环能力。

---

## P4.1：AI 参数配置自动化增强

> **目标**：从"JSONPath 单值提示"升级为"整块 inputParameters 智能生成"，大幅降低参数配置门槛。

### 当前痛点

- `ParameterSuggester` 仅提供单条 JSONPath 表达式提示，需用户逐一填写
- AI 没有工作流全局上下文（前序任务类型、工作流入参列表）
- 新增任务后参数完全空白，需人工逐字段填写
- 无法感知参数引用是否有效（引用了不存在的前序任务输出）

### P4.1.1：整体参数块 AI 自动生成

**功能描述**：在 `TaskDetailPanel` 的 inputParameters 编辑区增加"✨ AI 填充参数"按钮。点击后，AI 根据以下上下文自动生成完整的 `inputParameters` JSON 并填充到编辑器中。

**AI 上下文输入**：
```
- 当前任务类型 (taskType): HTTP / SIMPLE / INLINE / JSON_JQ_TRANSFORM / ...
- 当前任务名称与引用名
- 工作流 inputParameters 列表（可用的工作流入参名）
- 前序任务列表：[{ taskReferenceName, taskType, name }]
- 当前已填写的 inputParameters（用于增量补全）
```

**AI 输出**：标准 Conductor inputParameters JSON，可直接 apply 或用户在编辑器中调整后保存。

**交互流程**：
1. 用户点击"✨ AI 填充"按钮
2. 按钮变为 loading 状态（转圈）
3. AI 返回后，在编辑器中显示 diff 预览（新值 vs 当前值）
4. 用户点击"应用"确认，或"取消"保留原值

**涉及文件**：
- `src/components/TaskDetailPanel.tsx` — 新增 AI 填充按钮 + 触发逻辑
- `src/services/aiService.ts` — 新增 `generateTaskParameters(context)` 函数
- `src/components/AICopilot/ParameterSuggester.tsx` — 扩展为支持整块参数展示

### P4.1.2：参数引用有效性实时校验

**功能描述**：在参数值中检测 `${xxx.output.yyy}` 格式的引用，实时校验被引用的 `taskReferenceName` 是否存在于当前工作流的前序任务中。

**校验规则**：
| 场景 | 提示 |
|------|------|
| `${taskRef.output.field}` 中 `taskRef` 不存在 | ⚠️ 警告：任务引用不存在 |
| `${workflow.input.field}` 中 `field` 不在 `workflowDef.inputParameters` 中 | 💡 提示：工作流入参中未声明此字段 |
| `${taskRef.output.field}` 中 `taskRef` 是当前任务或后续任务（循环引用） | ❌ 错误：不能引用后续任务的输出 |

**涉及文件**：
- `src/utils/validator.ts` — 新增 `validateParameterReferences()` 校验规则
- `src/components/TaskDetailPanel.tsx` — 展示参数级别的 inline 警告图标

### P4.1.3：新增任务时 AI 参数预填（增强体验）

**功能描述**：用户在画布上新增任务节点（从侧边栏拖拽或点击 + 号添加）后，系统自动弹出 AI 参数建议 toast，提示"该任务有 3 个参数建议，点击查看"。

**智能推断逻辑**：
- HTTP 任务：根据工作流名称推断可能的 API 端点模式，建议 `uri`、`method`、常用 `headers`
- SIMPLE 任务：建议将前序任务的输出字段映射为输入
- INLINE 任务：根据上下文建议表达式骨架
- SUB_WORKFLOW：建议 `subWorkflowParam.name` 和 `subWorkflowParam.version`

**涉及文件**：
- `src/store/workflowStore.ts` — 在 `addNode` 后触发参数建议事件
- `src/components/TaskDetailPanel.tsx` — 首次打开时显示 AI 建议 banner

## P4.2：工作流入参配置与执行验证

> **目标**：在编辑模式下定义好工作流后，能直接填写工作流入参、触发真实执行、并在 run 模式下看到结果。

### 当前状态

- `WorkflowDef.inputParameters` 字段目前是 `string[]`（仅文档性，无结构）
- 没有从 IDE 内触发工作流执行的能力
- 执行数据只能通过外部注入（`importExecutionJSON` / `onLoadExecution` prop）

### P4.2.1：工作流入参 Schema 增强

**功能描述**：扩展 `WorkflowDef.inputParameters` 支持结构化定义，在 `WorkflowSettingsPanel` 中提供可视化编辑。

**新增类型定义**（`src/types/conductor.ts`）：
```typescript
export interface WorkflowInputParam {
  name: string;           // 参数名
  type?: 'string' | 'number' | 'boolean' | 'object' | 'array';
  description?: string;   // 用途说明
  required?: boolean;     // 是否必填
  defaultValue?: any;     // 默认值
  example?: any;          // 示例值（用于执行验证表单）
}
```

**向后兼容**：`inputParameters` 接受 `string[]`（旧格式）或 `WorkflowInputParam[]`（新格式），解析器自动处理两种格式。

**涉及文件**：
- `src/types/conductor.ts` — 新增 `WorkflowInputParam` 类型
- `src/components/WorkflowSettingsPanel.tsx` — 新增入参列表可视化编辑（增删改）

### P4.2.2：执行触发面板（WorkflowRunPanel）

**功能描述**：新增 `WorkflowRunPanel` 组件，在编辑模式下点击工具栏的"▶ 执行验证"按钮后弹出，用于填写工作流入参并触发执行。

**面板布局**：
```
┌─────────────────────────────────────────────┐
│ ▶ 执行验证：order-processing-workflow v1    │
├─────────────────────────────────────────────┤
│ 工作流输入参数                               │
│                                             │
│  orderId *    [________________]            │
│  userId        [________________]           │
│  amount        [________________]  number   │
│                                             │
│  [切换为 JSON 编辑器] ←→ [切换为表单模式]    │
│                                             │
│ ┌──────────────────────────────────────┐   │
│ │ {                                    │   │
│ │   "orderId": "ORD-001",              │   │
│ │   "userId": "user-123"               │   │
│ │ }                                    │   │
│ └──────────────────────────────────────┘   │
│                                             │
│         [取消]    [▶ 发起执行]              │
└─────────────────────────────────────────────┘
```

**执行流程**：
1. 用户点击"▶ 发起执行"
2. 调用 `onTriggerExecution(workflowName, version, inputData)`
3. 集成方返回 `{ workflowId: string }`
4. IDE 切换到 run 模式，显示 loading 状态
5. 调用 `onLoadExecution(workflowId)` 轮询（或集成方主动推送）执行结果
6. 加载执行实例后渲染运行态视图

**新增 Props**（`INTEGRATION.md` 中新增说明）：
```typescript
// WorkflowEditorProps 新增字段
onTriggerExecution?: (
  workflowName: string,
  version: number,
  input: Record<string, any>
) => Promise<{ workflowId: string }>;

onPollExecution?: (
  workflowId: string
) => Promise<WorkflowInstance | null>;

executionPollInterval?: number; // 轮询间隔（ms），默认 3000
```

**涉及文件**：
- `src/components/WorkflowRunPanel.tsx` — **新建**，执行触发面板
- `src/components/WorkflowRunPanel.css` — **新建**，面板样式
- `src/store/workflowStore.ts` — 新增 `runState`、`pendingExecutionId`、`executionPollTimer`
- `src/types/workflow.ts` — 新增执行触发相关类型
- `src/index.ts` — 导出新 Props 类型

### P4.2.3：执行状态轮询与自动切换

**状态机**：
```
edit → [用户点击执行] → executing（loading 覆盖层）
     → [onTriggerExecution 返回 workflowId] → run（run 模式，持续轮询）
     → [WorkflowInstance.status 为终态] → run（停止轮询，显示分析入口）
```

**新增 store 状态**：
```typescript
// WorkflowState 新增
runState: 'idle' | 'triggering' | 'polling' | 'done' | 'error';
pendingExecutionId: string | null;
executionError: string | null;
```

**轮询策略**：
- 初始间隔：2s
- 指数退避：每次轮询间隔 ×1.5，最大 15s
- 终态检测：`COMPLETED` / `FAILED` / `TIMED_OUT` / `TERMINATED` 后停止轮询

### P4.3.2：参数问题智能诊断

**功能描述**：自动解析常见 Conductor 错误模式，将原始错误映射到具体的参数配置问题，在面板中提供可操作的修复提示。

**错误模式识别库**（`src/utils/executionAnalyzer.ts`）：

```typescript
interface DiagnosticRule {
  pattern: RegExp;           // 匹配 reasonForIncompletion
  category: 'parameter' | 'timeout' | 'auth' | 'network' | 'logic';
  title: string;             // 简洁的问题标题
  explanation: string;       // 用户友好的解释
  suggestEditParam?: string; // 建议检查的参数字段名
}

const DIAGNOSTIC_RULES: DiagnosticRule[] = [
  {
    pattern: /NullPointerException.*inputData/i,
    category: 'parameter',
    title: '参数引用为空',
    explanation: '某个 inputParameters 字段引用的上游任务输出为 null，请检查 JSONPath 表达式',
    suggestEditParam: 'inputParameters'
  },
  {
    pattern: /PathNotFoundException|No results for path/i,
    category: 'parameter',
    title: 'JSONPath 路径不存在',
    explanation: '参数中的 JSONPath 表达式在实际数据中找不到对应路径',
    suggestEditParam: 'inputParameters'
  },
  {
    pattern: /HTTP (\d+).*uri/i,
    category: 'network',
    title: 'HTTP 请求失败',
    explanation: 'HTTP 任务请求失败，请检查 uri、method、headers 配置',
    suggestEditParam: 'uri'
  },
  {
    pattern: /timeout|timed.?out/i,
    category: 'timeout',
    title: '任务超时',
    explanation: '任务执行时间超过配置的超时阈值',
    suggestEditParam: 'timeoutSeconds'
  },
  // ... 更多规则
];
```

**展示方式**：
- 在 `ExecutionSummaryPanel` 的失败任务旁显示诊断卡片
- 诊断卡片包含：错误类别图标 + 问题标题 + 解释 + "去修复"按钮
- "去修复"按钮：切换到 edit 模式 → 选中该任务 → 定位到问题参数字段（高亮）

**涉及文件**：
- `src/utils/executionAnalyzer.ts` — 诊断规则引擎
- `src/components/ExecutionSummaryPanel.tsx` — 诊断卡片渲染

### P4.3.3：AI 执行诊断（AICopilot run 模式增强）

**功能描述**：在 run 模式下启用 AI Copilot，AI 可访问完整执行数据，支持自然语言诊断对话。

**核心能力**：
1. **自动故障摘要**：执行结束后（含失败），AI 自动生成执行报告摘要（1-3 句话）
2. **对话式诊断**：用户提问 "为什么 process_payment 任务失败了？" → AI 分析该任务的 input/output/error 给出诊断
3. **修复建议输出**：AI 生成 `WorkflowDiff` patch，用户可一键应用到 edit 模式

## 新增 Props 接口（公共 API）

```typescript
// WorkflowEditorProps 新增字段（src/index.ts 导出）

/**
 * 触发工作流执行。用户在 WorkflowRunPanel 中点击"发起执行"时调用。
 * 返回 workflowId 后 IDE 自动切换至 run 模式并开始轮询。
 */
onTriggerExecution?: (
  workflowName: string,
  version: number,
  input: Record<string, any>
) => Promise<{ workflowId: string }>;

/**
 * 轮询执行状态。IDE 在执行触发后按 executionPollInterval 间隔调用。
 * 返回 null 表示暂未获取到结果，返回 WorkflowInstance 则加载执行数据。
 * 返回终态（COMPLETED/FAILED/TIMED_OUT）后停止轮询。
 */
onPollExecution?: (
  workflowId: string
) => Promise<WorkflowInstance | null>;

/**
 * 执行轮询间隔（毫秒），默认 3000ms。
 * 内部使用指数退避，最大退避至 15000ms。
 */
executionPollInterval?: number;
```

## 交互原型示意

### 执行验证完整流程

```
[edit 模式]
  ↓ 工具栏点击"▶ 执行验证"
[WorkflowRunPanel 弹出]
  ↓ 填写入参 → 点击"发起执行"
[loading 覆盖层 + "执行中..."]
  ↓ onTriggerExecution 返回 workflowId
[自动切换 run 模式 + 轮询中]
  ↓ onPollExecution 返回 WorkflowInstance（执行中）
[run 模式：节点实时状态更新]
  ↓ 执行结束（FAILED）
[自动弹出 ExecutionSummaryPanel]
[AI 自动生成故障摘要]
  ↓ 点击失败任务的"去修复"
[切回 edit 模式，定位到问题参数]
```
