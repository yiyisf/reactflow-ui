### M1.3 AI 传输层反转（transport 三模式） 【2 人日】★ 本阶段核心

**API 设计**（`services/ai/transport.ts` 新增）：

```ts
export type AiTransport =
  | { type: 'endpoint'; url: string; headers?: Record<string, string> }
  | { type: 'custom'; stream: (req: AgentRequest, signal: AbortSignal) => AsyncIterable<StreamEvent> }
  | { type: 'direct'; provider?: 'openai' | 'anthropic' | 'auto'; apiKey: string; baseUrl?: string; model?: string };

export interface AgentRequest {          // endpoint 模式的 POST body，也是 custom 模式入参
  messages: Message[];                   // 现有 Message 类型（含 system/tool 角色）
  tools: ToolDef[];
  meta?: { sessionId?: string };
}
// StreamEvent 复用 protocolAdapter 现有事件：text | tool_call | error（+ 新增 usage）
```

- `AiConfig` 保持向后兼容：现有 `{ apiKey, provider, ... }` 自动视为 `direct` 模式；
  新增 `transport?: AiTransport` 优先生效。
- `endpoint` 模式：POST AgentRequest，响应为 SSE（`data: {StreamEvent}\n\n`），
  文档附一个 ~30 行 Node/Express 代理参考实现（服务端转发至 OpenAI/Anthropic）。
- `direct` 模式：保留现有 protocolAdapter 路径，但在 AiConfigPanel 与 README 标注
  「⚠️ 仅限开发调试——生产环境请使用 endpoint 代理模式」。
- `streamChat()` 收口为 `transport.stream()` 的统一出口，AiCommandCenter 调用方式不变。
- **验收**：demo 中三种模式各跑通一轮完整 agent 会话（direct 用真 key；endpoint 用本地
  参考代理；custom 用 mock 流）；`anthropic-dangerous-direct-browser-access` 仅出现在
  direct 分支。

### M1.4 草稿自动保存 + 会话恢复 【1.5 人日】

**API 设计**：

```ts
// AiWorkflowIDE props 新增
draftPersist?: { key: string } | false;          // 默认 false（不写宿主 localStorage）
onDraftChange?: (draft: IdeDraft) => void;        // 集成方自存后端的出口
// IdeDraft = { workflowDef, messages, pendingProposal, savedAt }
```

- 落 localStorage 的写入 debounce 500ms；挂载时检测到草稿 → 顶部横幅
  「已恢复 x 分钟前的编辑 · [放弃恢复]」。
- undo 栈不持久化（体积/复杂度不值得）；apiKey 维持不持久化。
- **验收**：编辑中刷新页面，workflowDef、对话、待确认提案完整恢复；
  `draftPersist: false` 时 localStorage 无新增 key。

### M1.5 错误出口两段式 + RepairCard 二次确认 【1 人日】

- 新增 `services/ai/errorMessages.ts`：HTTP 状态/网络错误 → 「发生了什么 + 你能做什么」
  中文文案映射（401→"AI 服务未授权，请联系管理员检查配置"；429→"请求过于频繁，请稍后重试"；
  网络→"无法连接 AI 服务，请检查网络"）。原始错误进 `onAiEvent`，不进聊天气泡。
- RepairCard 的 rerun/skip/retry 动作增加内联二次确认（点击后按钮变为
  「确认重跑 st_x？[确认] [取消]」），并补 `repair:confirmed` 审计事件。
- **验收**：断网/错 key/429 三种场景下，聊天中出现可理解文案 + 重试按钮；
  修复动作两次点击才触发 executionActions 回调。

### M1.6 API 冻结包（签名统一 + 类型收敛） 【1 人日】

- 执行回调统一为 WorkflowIDE 形态：
  `onTriggerExecution(name, version, input) => Promise<{ workflowId }>`；
  AiWorkflowIDE / WorkflowRunCard 迁移，`onPollExecution(workflowId) => Promise<WorkflowInstance | null>`。
- `AIServiceConfig` 标注 `@deprecated`，类型别名指向 `AiConfig`（实现收敛放 M3.3）。
- 公共 Props 消灭 `any`：`workflowExecution: WorkflowInstance | TaskExecutionData[]`、
  `onAiMetrics: (m: AiMetrics) => void`、`getAiMetrics(): AiMetrics`、CanvasPreview `onSave` 类型化。
- **验收**：`tsc --strict` 下集成方代码无隐式 any 泄漏；demo 两组件共用同一份执行适配器。

## M2 体验跃迁（目标：0.5.0 正式；对应 UX 方案 Phase A）

### M2.1 AgentRunner 抽取 【2.5 人日】★ M2 前置

- 新增 `services/ai/agentRunner.ts`：把 AiCommandCenter.handleSendText 的 agentic loop
  （多步循环、工具执行分发、self-heal、role 对齐补齐）整体迁出。

```ts
export interface AgentRunnerDeps {
  transport: AiTransport;
  tools: { defs: ToolDef[]; execute: (name, args, ctx) => Promise<ToolOutcome> };
  ctx: () => AgentContext;              // { workflowDef, libraryItems, mode, viewMode } — 由壳注入
  emit: (e: AgentUiEvent) => void;      // 结构化事件流，UI 唯一消费入口
}
export type AgentUiEvent =
  | { type: 'step:start'; index: number }
  | { type: 'text:delta'; content: string }
  | { type: 'tool:start' | 'tool:done'; name: string; summary?: string }
  | { type: 'selfheal'; errors: string[] }
  | { type: 'proposal' | 'plan' | 'repair' | 'clarification' | 'recommendation'; payload: ... }
  | { type: 'done' | 'error' | 'aborted'; ... };
```

- `pendingAutoSend` 机制删除，改为 `runner.send(text)` 直接调用（BusinessCanvas 点击、
  接受后追问等入口改造）。
- 同步完成服务层去 store 化：toolExecutor / contextEngine / systemPrompt 的
  `getState()` 全部改为经 `ctx()` 显式传参（架构审查 §3.1）。
- **验收**：AiCommandCenter 中不再出现 streamChat / executeToolCall 直接调用；
  Node 环境下可用 mock transport 跑通一轮 runner 单测。

### M2.2 UX Phase A：提案预览卡 + 提案可迭代 + 生成时间线 【4 人日】

按 UX 方案 P0-1/2/3 实施：

- **ProposalPreviewCard**（新组件）：以 proposedDef+diff 渲染业务步骤预览
  （复用 BusinessCanvas 的类型映射表抽出为 `utils/taskTypeMeta.ts`）；
  toolExecutor 的 diff 计算扩展**字段级摘要**（`modifiedDetails: { ref, changes: string[] }`，
  覆盖 retry/timeout/inputParameters/name 常见字段的中文描述）；
  Mermaid 前置到提案时刻渲染 proposedDef，接受后仅追加一行确认。
- **删除 guard 弹窗**：pending proposal 时输入可用；`buildSystemPrompt` 注入
  「当前存在未应用方案 JSON」上下文；新提案生成时旧卡折叠为灰色历史态。
  砍掉 ReviewBar 的逐项勾选 UI（`applyPartialProposal` 保留导出），ReviewBar 退化为
  与聊天卡同源的状态条。
- **AgentTimeline**（新组件）：消费 M2.1 的事件流渲染工作时间线，
  self-heal 显式化（"发现 N 处校验问题，正在自动修正"）；替换 toolStatus 单行。
- **验收**：对照 UX 方案验收基准 1–3（不开画布 10 秒看懂变更；≥3 个可见进度节点
  且自愈可见；提案悬挂时可继续对话零弹窗）。

## M3 结构化（目标：0.6.0；重构需 M2.4 测试兜底）

### M3.1 core 拆分 + 多入口固化 【3 人日】

- 目录重组：`src/core/`（types、parser、validator、diff、agentRunner、transport、
  workflowToMermaid、taskTypeMeta——零 React import）；`src/ide/`、`src/ai-ide/` 两壳。
- 入口：`.`（core re-export + WorkflowIDE）、`./ai`、（可选）`./core`。
- **验收**：`src/core` 内 `grep -r "from 'react'"` 为 0；三入口 build 通过。

### M3.2 store/registry 实例化（factory + Context） 【4 人日】★ 破坏面最大

- `createWorkflowStore(opts)` / `createAiStore()` / `createLibraryStore()`；
  registries 变为实例属性；`<IdeProvider>` 持有并注入。
- persist 改为 `persistKey?: string | false`（prefs 与 M1.4 草稿统一走此配置）。
- AiWorkflowIDE 中 5 段 prevRef+JSON.stringify 同步 effect 删除（初始化直接构造）。
- 迁移方式：新增 `useIdeStores()` hook 收口所有 store 访问，机械替换全部
  `useWorkflowStore/useAiStore/useLibraryStore` import（约 40 处）。
- **验收**：demo 新增"双实例并排"页面，两个 AiWorkflowIDE 独立编辑互不影响；
  卸载后重挂载无状态残留。

### M3.3 AI 栈收敛 + 共享外壳 【3 人日】

- AIChatPanel 迁移到 transport + tool-call 栈（保留"diff 审阅"产品行为，底层用
  `patch_workflow`）；`aiService.ts` 删除（M1.6 已 deprecated 一个版本）。
- 提取 `useIdeShell(props)`：def/execution 注入、外观同步（统一为"响应 prop 变化"）、
  temporal 清理（统一为"加载后清历史"）、onWorkflowChange（统一 skip-initial）、ref 基础集。
- 删除 CanvasPreview 透传层；`data-layout` 移到组件根节点 + ResizeObserver 按容器宽度断点。
- **验收**：两组件外观/undo/通知行为一致性用例通过；页面 documentElement 无组件写入。

### M3.4 UX Phase B：视觉系统整顿 【2 人日】

按 UX 方案 P1-5：SVG 图标组件替换界面级 emoji、Suggestion Slot 状态机收敛五套 chips、
AiCard 统一五种卡片基座、thinking 动画、token 化间距。
- **验收**：UX 方案验收基准 4（界面级 emoji 为 0、建议按钮 ≤3、卡片同源）。
