# v1.3.0 发布计划：自助接入

> 已发布：2026-10-24（原计划 2026-11-13） · 设计见 `docs/design/v1.3.0-自助接入设计.md` · 演进路线见 `docs/roadmap.md`

## 目标

新团队在测试环境里不靠平台方陪跑，也能自己完成"登记产品 → 规范命名建流程 → 接上已有接口 → 试跑 → 申请上线"。正值灯塔团队陪跑期，v1.3.0 在陪跑中途上线并按反馈修正。

## 批次

| 批次 | 内容 | 验收 | 计划 |
|---|---|---|---|
| ✅ B1（#54） | **扩展点注册**：`IdeProviders`、`WorkflowIdeProvider`、解析顺序与稳定性；**`TelemetrySink`** 核心（批量、flush、事件类型）；Demo `createMockProviders()` | 现有 `libraryProvider` 用法不变；同一 providers 同时服务两个 IDE；单测覆盖解析顺序与批量 | 10-26 – 10-29 |
| ✅ B2（#56） | **自助接入向导**：`OnboardingProvider` 契约、`WorkflowNameBuilder`、`OnboardingWizard`、`PromotionPanel`；工具栏入口与空画布引导；Demo 模拟实现 | 新用户在 Demo 中 5 分钟内完成产品登记 → 建流程 → 申请上线（模拟审批）；冲突、失败、生产环境三种降级可演示 | 10-30 – 11-05 |
| ✅ B3（#57） | **接口导入**：OpenAPI 3 / Swagger 2 / Postman v2.1 / curl 解析（均为 JSON，不支持 YAML），生成 HTTP 业务动作；敏感头占位 | 各格式至少 3 个真实样例的单测；生成的 HTTP 任务可在沙箱试跑 | 11-03 – 11-08 |
| ✅ B4（本批次）+ 宣传页（另一 PR） | **埋点铺设与收尾**：首批事件接入（含模板 / 专业模式试跑、专业模式新增步骤、`ide_opened` 去重）、接入指南与 CHANGELOG 更新、走查清单；**宣传页单独 PR，不在本批次** | 首批事件全部可在 Demo 控制台看到且不含参数值；走查清单通过 | 11-09 – 11-12 |

B2 与 B3 可并行。

## 需服务端配合（并行）

按《AI 实施指南》第九节：`/api/library/domains`、`/api/products/mine`、`/api/onboarding/trial`、`/api/onboarding/promote` 与进度查询；事件接收接口（可与 `wf_onboarding_event` 合用）。服务端未就绪时，内部项目可先用 Demo 的模拟实现联调界面。

## 已确认

已确认（设计文档第 7 节）：不支持 YAML；测试环境无所属产品时显示空画布引导；埋点先上首批事件。

## 人工走查清单（v1.3.0）

在 Demo（`npm run dev`）里逐项过一遍；每项都分别在暗色与亮色主题下看一次新增弹窗。埋点项打开浏览器控制台看 `[telemetry]` 分组。

### 扩展点与向后兼容
- [ ] 只传 `libraryProvider`（不用 `WorkflowIdeProvider`）时行为与 1.2.0 一致：流程库加载、版本固定与升级、分层过滤都不变，工具栏没有「新建流程」「申请上线」入口（「导入接口」不依赖 provider，始终可用）
- [ ] 同一个 `WorkflowIdeProvider` 同时服务 `WorkflowIDE` 与 `AiWorkflowIDE`；宿主每次渲染都新建 `providers` 对象时不会触发流程库重新加载
- [ ] 优先级：`libraryProvider` prop > 组件 `providers` > 外层 `WorkflowIdeProvider`
- [ ] 不配置 `onboarding` 与 `telemetry` 时界面与行为同 1.2.0，没有额外网络请求与定时器

### 自助接入向导
- [ ] 产品登记：测试环境下新用户登记产品成功，`trialEnabled` 为 false 时不出现试用入口
- [ ] 产品冲突：已被他人占用时提示联系负责人，已填内容保留
- [ ] 接口失败：断网 / 模拟失败时提示可重试，重试后继续，已填内容不丢
- [ ] 生产环境（Demo 顶栏切 PROD）：可在 `custom` / `std` 间选择；测试环境类型固定 `tmp`
- [ ] 三种起点：空白、模板（打开模板中心并保留向导生成的名称与说明）、接口导入（先建骨架再打开导入对话框）

### 命名生成器
- [ ] 实时预览与校验：非法字符、过长、缺少业务域 / 产品时给出提示，不可提交
- [ ] 层级写入后，动作选择器按分层规则过滤（L1 看不到 L2/L3，L2 看不到 L3）；宿主显式传了 `currentWorkflowLevel` 时以宿主为准

### 申请上线
- [ ] 仅 `tmp` 类型流程出现「申请上线」；`custom` / `std` 预览的正式名称正确
- [ ] 提交后进度刷新（2 秒起指数退避、30 秒封顶），状态依次 SUBMITTED → REVIEWING → APPROVED → SYNCED
- [ ] 被驳回时显示驳回原因并允许重新提交；关闭弹窗后轮询停止

### 接口导入
- [ ] OpenAPI 3、Swagger 2、Postman v2.1、curl 各导入一次（Demo 样例见 `public/sample-imports/`），预览列表可多选，确认后追加为步骤
- [ ] 敏感头（`Authorization`、`Cookie`、`X-Api-Key`、名称含 token / secret / api-key 的头、curl `-u`）被替换为 `${workflow.input.xxx}` 占位并有提示；保存后的流程定义里搜不到真实值
- [ ] 文件上传：选择 `.json` / `.txt` 文件能读入；超大或非文本文件有友好提示；YAML 提示「请先转为 JSON」
- [ ] 业务模式与专业模式都能打开；导入的 HTTP 任务能在沙箱试跑，重新打开仍还原为同一动作

### 埋点
- [ ] 控制台依次能看到：`ide_opened`（刷新一次只有一条，StrictMode 下也是一条）、`trial_started`、`workflow_created`、`step_added`（`builtin` / `library` / `import` / `template`）、`api_imported`、`sandbox_run`（三种 `entry`：业务卡片、模板中心、专业模式各试跑一次，每次只有一条）、`workflow_saved`、`promotion_requested`、`promotion_state`；`AiWorkflowIDE` 里还有 `ai_event`
- [ ] 所有事件的 `props` 只有名称类简单值，不含参数值、表达式、请求头、提示词与对话内容
- [ ] 不配置 `telemetry` 时控制台没有 `[telemetry]` 输出

### 空画布引导
- [ ] 仅 `WorkflowIDE`：配置了 `onboarding`、`trialEnabled` 为 true、用户没有所属产品、画布上没有流程、未被关闭、向导未打开时显示「开始试用」卡片
- [ ] 以下任一情况不显示：生产环境 / 已有产品 / 已有流程 / 点击关闭后 / 向导已打开 / 未配置 `onboarding`；`AiWorkflowIDE` 不显示（只提供工具栏入口）

### AI IDE 工具栏
- [ ] `AiWorkflowIDE` 配置 `onboarding` 后工具栏出现「新建流程」「申请上线」；向导起点只有空白（该 IDE 暂无模板中心与接口导入入口）
- [ ] 新建与申请上线的埋点与 `WorkflowIDE` 一致；`ai_event` 只含 `type`

### 主题与键盘
- [ ] 暗色 / 亮色下检查：向导、命名生成器、申请上线弹窗、接口导入对话框、空画布引导卡片的背景、文字、边框、按钮对比度正常
- [ ] Esc 关闭最上层弹窗且不误关下层；焦点落在弹窗内并被限制在弹窗内循环（Tab / Shift+Tab），关闭后焦点回到触发按钮
- [ ] 弹窗内按钮可只用键盘操作，表单校验错误能被读到（`aria` 提示）

### 已知缺口（不阻塞发布）
- 专业模式的「模拟运行」动画（`startSimulation`）不上报埋点，它只演示流转，不执行沙箱
- `AiWorkflowIDE` 暂无模板中心与接口导入入口，对应事件仅 `WorkflowIDE` 上报
- 宣传页由单独的 PR 提交，不在 B4 本批次内
