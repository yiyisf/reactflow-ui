# FlowGov 工作流设计器与运行监控 - 设计规范文档

## 1. 设计概述

### 1.1 设计目标
- **统一视觉语言**：定义模式与监控模式使用相同的排版策略和节点形状
- **自动智能排版**：根据任务数量和结构自动计算最优布局
- **清晰状态表达**：运行态颜色体系清晰无歧义
- **高效操作体验**：支持快速搜索、快捷添加、便捷配置

### 1.2 核心设计原则
1. **一致性**：相同任务类型在定义和监控模式下保持相同形状
2. **可识别性**：不同任务类型通过形状+图标+颜色三重区分
3. **层次清晰**：嵌套结构通过缩进、边框、背景色区分层级
4. **状态明确**：执行状态通过饱和度差异化的颜色体系表达

### 3.4 状态色彩设计原则

1. **语义明确**：绿色=成功，红色=失败，蓝色=进行中，灰色=未开始/取消
2. **饱和度区分**：主状态使用高饱和度，次要状态使用低饱和度
3. **无歧义**：避免使用可能混淆的相近色彩
4. **对比度**：确保在深色背景上有足够的可读性

## 4. 自动排版算法

### 4.1 排版策略

```
布局方向：从左到右（LTR）为主，支持从上到下（TTB）

基础间距：
- 节点水平间距：80px
- 节点垂直间距：60px
- 层级缩进：40px
- 容器内边距：24px

自动排版规则：
1. 顺序任务：水平排列，超过5个自动换行
2. 并行分支：垂直展开，自动计算分支高度
3. 条件分支：菱形节点居中，分支路径等距分布
4. 循环任务：使用容器包裹，显示循环边界
5. 嵌套结构：递归计算子结构尺寸，动态调整父容器
```

### 4.2 节点位置计算

```javascript
// 伪代码：自动布局算法
function calculateLayout(workflow) {
  const nodes = workflow.tasks;
  const layout = new LayoutEngine();
  
  // 第一遍：计算每个节点的尺寸
  nodes.forEach(node => {
    node.size = calculateNodeSize(node);
  });
  
  // 第二遍：计算层级和分组
  const levels = groupByDependency(nodes);
  
  // 第三遍：计算位置
  let currentX = MARGIN_LEFT;
  levels.forEach((level, levelIndex) => {
    let maxWidth = 0;
    let currentY = MARGIN_TOP;
    
    level.forEach(node => {
      if (isParallelContainer(node)) {
        // 并行容器：垂直展开子节点
        node.position = { x: currentX, y: currentY };
        currentY += calculateParallelHeight(node) + VERTICAL_GAP;
      } else {
        node.position = { x: currentX, y: currentY };
        currentY += node.size.height + VERTICAL_GAP;
      }
      maxWidth = Math.max(maxWidth, node.size.width);
    });
    
    currentX += maxWidth + HORIZONTAL_GAP;
  });
  
  return layout;
}
```

### 4.3 连接线路由

```
连接线类型：
1. 直线连接：用于相邻的顺序节点
2. 折线连接：用于跨层级或非相邻节点
3. 曲线连接：用于分支汇合点

路由规则：
- 避免线条穿过节点
- 分支线条使用等角度分布
- 循环回边使用曲线，从右侧绕回左侧
- 支持手动调整锚点位置
```

## 10. 技术实现建议

### 10.1 推荐技术栈

```
前端框架：React 18 + TypeScript
画布库：ReactFlow 11.x
状态管理：Zustand / Redux Toolkit
样式方案：TailwindCSS + CSS Variables
图标库：Lucide React
动画库：Framer Motion
```

### 10.2 性能优化

```
1. 虚拟化渲染：超过100个节点启用视口裁剪
2. 节点懒加载：复杂节点内容按需渲染
3. 缓存策略：布局计算结果缓存
4. Web Worker：布局计算放入Worker
5. 增量更新：仅更新变化的节点
```
